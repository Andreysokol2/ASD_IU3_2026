# Задача 12. Пара с заданной суммой

## Решение
Если перебирать все пары двумя циклами:

```java
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == s) ...
```

то проверок будет n(n-1)/2, при n = 10^5 это ~5·10^9 — слишком долго.

Поэтому храню в `HashMap` для каждого значения индекс его первого появления и иду по j:
1. ищу `s - a[j]` в map — если нашёл, это i, самый левый для этого j;
2. после этого кладу `a[j]` в map через `putIfAbsent`, чтобы остался первый индекс. Кладу после проверки, чтобы элемент не сложился сам с собой.

Почему ответ с наименьшим i и потом наименьшим j: j идёт по возрастанию, значит для любого i его пара с самым маленьким j попадётся раньше остальных. Поэтому ответ обновляю только если новый i меньше.

`s` и ключи в `long`, потому что `s - a[j]` может выйти за int.

## Асимптотика

```java
Map<Long, Integer> first = new HashMap<>();
for (int j = 0; j < a.length; j++) {                  // n итераций
    Integer i = first.get(s - a[j]);                  // O(1) в среднем
    if (i != null && (bestI == -1 || i < bestI)) {    // O(1)
        bestI = i;
        bestJ = j;
    }
    first.putIfAbsent((long) a[j], j);                // O(1) в среднем
}
```

T(n) = n · O(1) → **O(n)** в среднем (у HashMap операции O(1) в среднем)

Память: в map до n записей → **O(n)**.

## Тесты
- обычная пара;
- пара с меньшим i находится позже → выбирается меньший i;
- `5 5 5`, s = 10 → (0, 1), наименьший j;
- одна пятёрка, s = 10 → элемент нельзя брать дважды, ответ -1 -1;
- вывод `main`.
